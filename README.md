# 食光 · 每日饮食日记

一个用中文记录一日三餐、食材份量和大致营养的网站。奶油白与橄榄绿界面，支持手机和电脑。

网站：[打开食光](https://jack-diet-journal.realjackye.chatgpt.site)。Sites 部署默认仅本人可访问，需要用创建网站的 ChatGPT 账户登录。

## 已整理的记录

- **2026-10-23**：早餐燕麦水果坚果全脂牛奶碗和两个鸡蛋；午餐鸡胸肉、黑面包芝士、橄榄油黑醋蔬菜沙拉；第三餐燕麦碗保留为计划。
- **2026-10-24**：同配方早餐；午餐阿根廷草饲眼肉牛排约250g生重、黑面包芝士；辛拉面配干香菇、豆芽保留为晚餐计划。

来源是用户提供的[分享对话](https://chatgpt.com/share/6add1657-97b8-83ec-851d-d51b066fd4be)。归档日期采用北京时间；用户已更正第二天的实际食用日期为2026-10-24，2026-10-25是报告日期。原始消息时间与稳定餐食ID保留，餐食内容和计划状态不变。没有提供饮食的日期留白，不自动补数据。只保存饮食相关信息，不复制对话中的其他个人信息。

## 使用

需要 Node.js 20 或以上，无需安装第三方依赖：

```sh
npm run dev
```

打开终端打印的 `http://127.0.0.1:4173`。生产构建：

```sh
npm run check
npm test
npm run build
```

构建生成 `dist/server/index.js`，它同时提供页面和自然语言解析接口，需要支持 Cloudflare Worker ESM 的服务端运行环境。Sites 已配置对应部署；GitHub Actions 运行检查、测试和构建。GitHub Pages 只能托管静态文件，无法运行本项目的 DeepSeek 服务端接口。

## 口述一餐或一整天

首页直接展开饮食月历，点击日期即可展开当天的餐食与估算；可以切换月份、回到今天，或收起日期详情。点击“记录饮食”进入独立的记录页面，在“自然语言”和“填写表格”之间选择。

“自然语言”支持输入文字、手机键盘语音和浏览器直接口述。例如：

> 今天早餐吃了两个鸡蛋和250毫升牛奶。

> 昨天早餐吃了燕麦碗，中午吃了一碗米饭和鸡胸肉，晚餐准备吃番茄鸡蛋面。

说完后可检查文字，再点“整理并记录”。DeepSeek 将文字拆成实际提到的餐次，成功后自动填到对应日期的早餐、午餐、晚餐或加餐卡片；可以继续记录、撤销，或点击“查看记录的日期”返回月历。表格方式可逐项填写食材与份量，保存后回到对应日期。同餐次已有食物时口述结果追加到原卡片，保留其他餐次；可编辑，也可撤销这次填入。没有说哪一餐时，可从下拉菜单选餐次。缺少必要信息会提示补充，失败会保留文字；重复点击和同次重试不会重复加餐。

“今天、昨天”以北京时间当前日期换算；没有提日期时使用表单里的“吃饭的日期”。计划吃和实际吃过继续分开统计。份量未给时粗估并标注；已有食材使用参考库计算，其他食物使用 AI 粗估，不补造未提及的餐食。

直接口述依赖浏览器的 `SpeechRecognition` / `webkitSpeechRecognition`、网络与麦克风权限，部分浏览器不支持；可随时改用手机键盘语音输入或打字。语音识别可能由浏览器的语音服务处理。页面不会上传音频给 DeepSeek；点整理时，服务端将口述文字、食材参考和必要的已知饮食配方发送给 DeepSeek。

整理结果沿用网站原有的**本机草稿**保存方式，不会自动提交 GitHub。跨设备归档仍请导出日记，交给 Codex 合并发布。

### API Key

生产环境使用 Sites 的服务端秘密变量 `DEEPSEEK_API_KEY`；`DEEPSEEK_MODEL` 当前为 `deepseek-flash`。真实 Key 不写入源码、页面、浏览器存储或构建产物。`.env.example` 只列变量名称。本地可使用未跟踪的 `.env`（Node.js 22）：

```sh
node --env-file=.env scripts/serve.mjs
```

调用采用 [DeepSeek 官方 JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)和[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)；服务端校验结构、日期、餐次、份量和营养数值，并处理账户、限流、超时和不完整输出。API 仅在现有本人访问范围内使用，不能把站点改成公开而不同时增加接口鉴权。

## 每天通过对话继续记录

在这个 Codex 对话里告诉我日期、吃过的食物、大致份量和做法即可，例如：

> 今天午餐吃了150g熟米饭、200g炒西兰花、两个鸡蛋，用油大概5g。昨天计划的泡面没有吃。

后续更新会将真实饮食追加到 `data/diary.json`，复用已确认的配方，标注需要估算的份量，运行检查后同步仓库与网站。`AGENTS.md` 保存了这套维护约定。这是收到对话后的更新流程，不会自动读取其他聊天，也没有设置定时提醒。

也可以在网站内新增、编辑餐食或确认计划餐已吃。这些操作**保存到当前浏览器的本机草稿**，不会直接写入 GitHub。通过“导出日记”备份，再将导出的 JSON 交给 Codex 合并进仓库后，各设备才能读取同一份已发布记录。导入时相同日期、相同餐食 ID 会更新，其他餐食保留；导入文件只作为数据，不执行内容。

```sh
# 合并一天或整份网站导出的日记 JSON
npm run record -- --input path/to/day-or-diary.json
```

数据合并通过校验后才原子写入；重复运行同一输入不会重复增加相同 ID 的餐食。

## 估算方式

食材库 `data/foods.json` 使用 [USDA FoodData Central 官方 SR Legacy 数据](https://fdc.nal.usda.gov/download-datasets/)与[农心日本官网标签](https://www.nongshim.co.jp/lineup/lineup01_01.html)。保存每100g可食部的热量、蛋白质、碳水、脂肪、膳食纤维和饱和脂肪，按份量换算。界面显示来源，可展开每项食材查看份量依据。

- 已吃和计划分开保存，**摄入总量仅合计已吃餐食**。
- 生重、熟重、干重分别标注。燕麦100g尚未确认干熟，暂按干重；鸡胸肉150–200g取175g，暂按熟重。
- 一根香蕉暂按可食部118g，两个鸡蛋暂按去壳100g；浆果、面包、芝士、蔬菜与调味量为估算。
- 牛奶250ml暂按250g计算；具体品牌和密度会有差异。肉类额外用油只有用户提供后才计入。
- 眼肉使用澳洲草饲含脂生眼肉近似阿根廷草饲眼肉。辛拉面暂按日本版120g/500kcal，实际以手中包装校正。
- 未知营养素保留 `null`；总量不完整时显示“—”，不会把未知记成0。未记录日期不计入均值。

## 文件

```text
data/diary.json          跨设备发布的真实饮食记录
data/foods.json          带来源的食材参考库
site/                   静态前端与共享计算/校验函数
site/quick-entry.js      文字与浏览器语音入口
site/quick-merge.mjs     按餐次合并、重复提交保护与撤销
server/                 DeepSeek服务端解析和HTTP接口
scripts/record-day.mjs   追加与更正记录
scripts/check.mjs        数据一致性检查
tests/                  统计、合并、校验测试
.openai/hosting.json     Sites 部署身份与Worker配置
```

饮食数据随源码进入本仓库；仓库目前为用户指定的公开仓库。浏览器草稿仅留在本机，清除站点数据会失去未导出的草稿。
