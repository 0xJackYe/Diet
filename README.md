# 食光 · 每日饮食日记

一个用中文记录一日三餐、食材份量和大致营养的网站。奶油白与橄榄绿界面，支持手机和电脑。

网站：[打开食光](https://jack-diet-journal.realjackye.chatgpt.site)。Sites 部署默认仅本人可访问，需要用创建网站的 ChatGPT 账户登录。

## 已整理的记录

- **2026-10-24**：同配方早餐；午餐阿根廷草饲眼肉牛排约250g生重、黑面包芝士；辛拉面配干香菇、豆芽保留为晚餐计划。

来源是用户提供的[分享对话](https://chatgpt.com/share/6add1657-97b8-83ec-851d-d51b066fd4be)。归档日期采用北京时间；用户已更正第二天的实际食用日期为2026-10-24，2026-10-25是报告日期。原始消息时间与稳定餐食ID保留，餐食内容和计划状态不变。没有提供饮食的日期留白，不自动补数据。只保存饮食相关信息，不复制对话中的其他个人信息。

## 使用

需要 Node.js 20 或以上，无需安装第三方依赖：

```sh
npm run dev
```

打开终端打印的 `http://127.0.0.1:4173`。生产构建：

```sh
npm run check
npm test
npm run build
```

`dist/` 可放到支持静态文件的网站托管服务。所有资源使用相对路径，也可部署在 GitHub Pages 仓库路径下。`.github/workflows/pages.yml` 支持从 main 分支构建；在仓库 Settings → Pages 选择 GitHub Actions 后生效。GitHub Pages 的访问范围由 GitHub 仓库与 Pages 设置决定，和默认私有的 Sites 网站不同。

## 每天通过对话继续记录

在这个 Codex 对话里告诉我日期、吃过的食物、大致份量和做法即可，例如：

> 今天午餐吃了150g熟米饭、200g炒西兰花、两个鸡蛋，用油大概5g。昨天计划的泡面没有吃。

后续更新会将真实饮食追加到 `data/diary.json`，复用已确认的配方，标注需要估算的份量，运行检查后同步仓库与网站。`AGENTS.md` 保存了这套维护约定。这是收到对话后的更新流程，不会自动读取其他聊天，也没有设置定时提醒。

也可以在网站内新增、编辑餐食或确认计划餐已吃。这些操作**保存到当前浏览器的本机草稿**，不会直接写入 GitHub。通过“导出日记”备份，再将导出的 JSON 交给 Codex 合并进仓库后，各设备才能读取同一份已发布记录。导入时相同日期、相同餐食 ID 会更新，其他餐食保留；导入文件只作为数据，不执行内容。

```sh
# 合并一天或整份网站导出的日记 JSON
npm run record -- --input path/to/day-or-diary.json
```

数据合并通过校验后才原子写入；重复运行同一输入不会重复增加相同 ID 的餐食。

## 估算方式

食材库 `data/foods.json` 使用 [USDA FoodData Central 官方 SR Legacy 数据](https://fdc.nal.usda.gov/download-datasets/)与[农心日本官网标签](https://www.nongshim.co.jp/lineup/lineup01_01.html)。保存每100g可食部的热量、蛋白质、碳水、脂肪、膳食纤维和饱和脂肪，按份量换算。界面显示来源，可展开每项食材查看份量依据。

- 已吃和计划分开保存，**摄入总量仅合计已吃餐食**。
- 生重、熟重、干重分别标注。燕麦100g尚未确认干熟，暂按干重；鸡胸肉150–200g取175g，暂按熟重。
- 一根香蕉暂按可食部118g，两个鸡蛋暂按去壳100g；浆果、面包、芝士、蔬菜与调味量为估算。
- 牛奶250ml暂按250g计算；具体品牌和密度会有差异。肉类额外用油只有用户提供后才计入。
- 眼肉使用澳洲草饲含脂生眼肉近似阿根廷草饲眼肉。辛拉面暂按日本版120g/500kcal，实际以手中包装校正。
- 未知营养素保留 `null`；总量不完整时显示“—”，不会把未知记成0。未记录日期不计入均值。

## 文件

```text
data/diary.json          跨设备发布的真实饮食记录
data/foods.json          带来源的食材参考库
site/                   静态前端与共享计算/校验函数
scripts/record-day.mjs   追加与更正记录
scripts/check.mjs        数据一致性检查
tests/                  统计、合并、校验测试
.openai/hosting.json     Sites 部署身份与输出目录
```

饮食数据随源码进入本仓库；仓库目前为用户指定的公开仓库。浏览器草稿仅留在本机，清除站点数据会失去未导出的草稿。
